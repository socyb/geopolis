02¿Qué es Git?

Un programa que guarda la historia completa de una carpeta.

  • Cada versión guardada es un commit: una foto de todos los archivos + un mensaje.
  • Puedes volver a cualquier foto anterior.
  • Funciona en tu computadora, sin internet.
  • Lo creó Linus Torvalds (2005) para programar Linux.

Analogía

Es como los "puntos de guardado" de un videojuego, o como el historial de versiones de Google Docs… pero para todo un proyecto, con nombre y fecha en cada cambio.

04¿Qué es GitHub?

Git es la herramienta. GitHub es el lugar donde se guardan los repositorios en internet.

☁️ Respaldo

Tu proyecto vive en la nube, con toda su historia.

👥 Colaboración

Pull requests: propuestas de cambio que se revisan antes de unirse.

🌐 GitHub Pages

Convierte un repo con HTML en un sitio web gratis.

Es de Microsoft desde 2018. Alternativas: GitLab, Bitbucket, Codeberg.

05GitHub Pages: de archivo a sitio

  • Un archivo .html es solo texto con instrucciones de formato.
  • Pages toma el repo y lo sirve tal cual:
    recursos/equipos.html → socyb.github.io/geopolis/recursos/equipos.html
  • index.html es la "portada" que se abre por defecto.

Página "no vinculada"

Como esta: existe y tiene URL, pero ningún menú apunta a ella. Solo la encuentra quien tiene el enlace.

Útil para borradores, presentaciones o material en preparación.

06Claude como agente

Chatbot

Tú preguntas → responde texto.
Tú copias, pegas, guardas, subes.

Agente

Tú describes la meta → él actúa: lee archivos, ejecuta comandos, edita, prueba y hace commit.

El ciclo del agente: pensar → usar una herramienta → ver el resultado → repetir hasta terminar.

Claude Code trabaja dentro de una copia del repositorio, igual que lo haría una persona en su computadora.

09Trabajar desde una IDE: VS Code

Una IDE es el "procesador de textos" del código. Visual Studio Code es gratis y la más usada.

  1. Instala VS Code y Git.
  2. Inicia sesión con GitHub (ícono de cuenta).
  3. Clone Repository → elige geopolis.
  4. Edita y usa el panel Source Control para commit y push sin terminal.

Agentes dentro de VS Code

  • Claude Code: extensión oficial (o en la terminal).
  • GitHub Copilot: chat y modo agente; deja elegir modelo (Claude, GPT, Gemini…).
  • Extensión Live Preview: ver el HTML mientras editas.

10¿Y ChatGPT, Gemini y otros?

OpenAI · ChatGPT

  • Codex: el agente de código de OpenAI; se conecta a GitHub y abre pull requests.
  • Codex CLI y extensión para VS Code.
  • ChatGPT puede leer repos con el conector de GitHub.

Google · Gemini

  • Gemini CLI: agente en terminal, con nivel gratuito.
  • Gemini Code Assist para VS Code.
  • Jules: agente que trabaja sobre tu repo de GitHub.

Otros

  • Copilot (multimodelo).
  • Cursor, Windsurf: editores con IA.
  • Ollama: modelos abiertos (Llama, Qwen, DeepSeek) en tu propia PC.

La lógica es la misma: agente + repositorio + Git. Cambia el modelo, no la ruta.

11¿Qué es un LLM?

Large Language Model: un programa entrenado con enormes cantidades de texto para hacer una sola cosa…

predecir la siguiente palabra.

Repitiendo esa predicción, palabra tras palabra, escribe ensayos, código o esta presentación. Claude, GPT, Gemini y Llama son LLMs.

12El abuelo: las cadenas de Markov

Andréi Márkov (1913) contó, en el poema Eugenio Oneguin, con qué frecuencia una letra sigue a otra.

Idea: el siguiente estado depende solo del actual, con cierta probabilidad.

Toca una palabra y mira qué podría venir después, según este mini-corpus:

elige al azar según las probabilidades

13De Markov a los LLMs

Cadena de MarkovLLM (Transformer)
Mira hacia atrás1 o 2 palabrasCientos de miles de tokens
AprendeContando frecuenciasAjustando miles de millones de pesos
Entiende relacionesNoSí: mecanismo de atención
ResultadoFrases rarasTexto coherente, razonamiento, código

En el fondo sigue siendo lo mismo: probabilidades de lo que sigue. Por eso puede sonar seguro… y equivocarse.

14Redes neuronales y pesos

  • Una neurona artificial multiplica cada entrada por un peso, suma todo y decide cuánto "se activa".
  • Miles de neuronas en capas forman una red.
  • Entrenar = ajustar los pesos poco a poco para equivocarse menos (descenso del gradiente + backpropagation).
  • Los "parámetros" de un LLM son esos pesos: miles de millones.

16Tokens, contexto y alucinaciones

Token

El modelo no lee palabras sino trozos: geo·polí·tica. Aproximadamente ¾ de palabra.

Contexto

Todo lo que el modelo "ve" a la vez: tu prompt, los archivos, la conversación. Lo que no está ahí, no lo sabe.

Alucinación

Cuando predice algo plausible pero falso: citas, enlaces, fechas. Siempre verifica.

Consecuencia práctica: la calidad de lo que das determina la calidad de lo que recibes.

17Programar = escribir con claridad

“El lenguaje de programación más nuevo y de moda es el inglés.”

— Andrej Karpathy, 2023 (léase: el español, o cualquier lengua)

“Sobre la necedad de la programación en lenguaje natural.”

— Edsger Dijkstra, 1978: la ambigüedad de la lengua es justo lo que el código formal evitaba.

Los dos tienen razón: hoy el código se escribe en lengua humana, y por eso la precisión pasa del compilador a quien escribe.

Las soft skills (redactar, argumentar, explicar, escuchar, delimitar un problema) se volvieron habilidades técnicas.

18El lenguaje “natural” no es natural

Saussure

El signo es arbitrario y convencional: nada en "mapa" se parece a un mapa. Es un acuerdo social.

Wittgenstein

El significado es el uso dentro de un "juego de lenguaje". “Los límites de mi lenguaje son los límites de mi mundo.”

Bourdieu · Foucault

Hablar es una práctica aprendida, atravesada por poder, capital cultural y discursos.

Lo llamamos “natural” solo porque lo aprendimos de niños. Es una tecnología cultural, y como toda tecnología se puede usar con más o menos oficio.

Para el agente, tus palabras son literalmente el programa: lo que es ambiguo para una persona también lo es para la máquina.

19Cómo pedir las cosas

El agente no adivina tu intención: completa lo que falta con lo más probable, que suele ser lo más genérico.

  • Objetivo: qué quieres y para qué.
  • Audiencia y uso: ¿proyector, celular, imprimir?
  • Contexto: archivos, ejemplos, datos.
  • Restricciones: lo que no debe hacer.
  • Formato: dónde guardar, cómo nombrar.
  • Criterio de éxito: cómo sabrás que quedó bien.

Escribe como si se lo explicaras a un asistente brillante que acaba de llegar y no conoce tu proyecto.

21Tips para mejores diseños

  • Da referencias: "como la página de equipos", una captura, un sitio que te guste.
  • Nombra el ambiente: sobrio, editorial, periodístico, lúdico…
  • Paleta y tipografía si las tienes: "azul UNAM y dorado".
  • Di dónde se verá: proyector, celular, impresión.
  • Itera en pasos chicos: un cambio por mensaje.
  • Señala con precisión: "el título de la diapositiva 4", no "eso de arriba".
  • Pide que lo pruebe: "revisa que no se desborde en 1280×720".
  • Explica el porqué: "más grande porque se ve desde el fondo del salón".

23Flujo de trabajo recomendado

  1. Describe la tarea con contexto y restricciones.
  2. El agente trabaja en una rama propia, nunca directo en main.
  3. Revisa el resultado: ábrelo, pruébalo en el proyector o el celular.
  4. Pide ajustes concretos hasta que quede.
  5. Commit + pull request → revisas → merge → Pages publica.

Si algo sale mal, Git guarda la historia: siempre se puede volver atrás.

En resumen

Git guarda. GitHub comparte.
El agente construye.
Tú decides qué y cómo.

Un LLM predice lo que sigue; un buen prompt hace que "lo que sigue" sea lo que tú querías.
